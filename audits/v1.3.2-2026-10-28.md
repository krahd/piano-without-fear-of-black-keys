# Audit — *Piano Without Fear of Black Keys*, v1.3.2

**Audit date:** 28 October 2026  
**Baseline:** GitHub \`main\` at \`854c0dd5f5ba4091c0f1d99a3d49f0df341377fa\` (27 October 2026)  
**Published edition:** v1.3.2, 53 pages, 160 × 230 mm, stable root filename \`Piano_Without_Fear_of_Black_Keys.pdf\`.  
**Scope:** The stated **transposition-first practical manual** remains the brief, including its beginner and experienced-player routes. The **separate new book** on musical knowledge/instrumental geometry is not an alternative brief for this audit.  
**Publication state:** Review only. No book text, PDF, stylesheet, diagrams or public link is modified.

## Verdict

**The v1.3.2 errata repair is correct and suitably bounded.** The twelve Appendix B whole-tone final notes now agree with the displayed \`1 2 3 #4 #5 b7\` formula (e.g. C = \`C D E F# G# Bb\`; Db = \`Db Eb F G A Cb\`). The pitches, rather than merely their names, are unchanged. A well-scoped table-validation suite now tests 180 scale rows and 108 chord-family cells (288 sequences) for degree spellings and pitch classes, and checks convenience-source synchronisation. This materially reduces a previously identified class of errors.

**But this is not a comprehensive repair of the book.** Almost all pedagogical and production weaknesses from the v1.3.1 audit remain, and a **new release integrity problem** has appeared: the historical edition builders now read a source revised for v1.3.2. The manual remains useful as a theory/transposition reference, but the practical exercises and book production do not yet justify treating it as pedagogically validated or print-ready.

Severity: **P0** publication/data-integrity risk or fundamental musical error; **P1** substantive correctness/learning/production defect; **P2** worthwhile editorial, accessibility or hygiene issue. Confidence describes what was actually checked.

## Findings

### P0 / release integrity — historical build scripts are now fed newer manuscript text

**Verified from build-script sources.** The v1.3.1 builder reads \`../../piano_transposition_manual.md\` (current, corrected v1.3.2), changes only cover strings, and renders into \`edition-design/v1.3.1/Piano_Without_Fear_of_Black_Keys_v1.3.1.pdf\`. Its \`COVER_CHANGE_ONLY\` assertion tests equality of body text *against the current manuscript*, not against a pinned 1.3.1 snapshot. The v1.3 historical shell script likewise reads current \`piano_transposition_manual.md\` and writes directly over \`edition-design/v1.3/Piano_Without_Fear_of_Black_Keys_v1.3.pdf\`.

**Consequence:** Re-running either archived build after publication of v1.3.2 incorporates the new whole-tone spellings under the old cover and can silently overwrite an **historical release artefact**. Even if the PDF bytes were already nondeterministic because of renderer versions, the **edition text itself** would be wrong for the claimed archival version.

**Remedy:** Pin the precise source (Git commit or immutable, checked-in release snapshot) for each historical build; prefer a distinct archive build output path and guard against overwriting archived binaries; assert expected input hash and fail on mismatch. Document the source/renderer/font/tool versions and distinguish bitwise reproduction from functional reproduction. The existing archived PDFs themselves have **not** been modified by this audit.

### P1 / musical precision — transposition example still calls different chords the “identical” object

**Verified in current manuscript, Part II §4.** Cmaj7 and D♭maj7 are both \`1 3 5 7\`, but the text says “The musical object is identical; only its keyboard realization changes.” In a manual built around the distinctions between pitch class, sounding pitch, formula and fingering, this elides **invariant chord quality/interval structure** with **changed actual pitches**.

**Remedy:** One-sentence correction: “Both use \`1 3 5 7\`. The formula is unchanged; the notes and keyboard geometry are not.” No chapter rewrite is required.

### P1 / practice — the main translation pipeline lacks a complete worked case

**Verified in current manuscript, Preface and Part V §16.** The principal example \`Am – F – C – G\` → \`Bbm – Gb – Db – Ab\` stops at chord names/functions. The method claims an explicit sequence **source notes → degree formula → target pitch classes → register → target geometry** but never finishes this example with named octave positions and a playable voicing across the entire progression.

**Remedy:** Add *one* fully reproducible two- or four-chord transposition with original sounding notes, resulting chord-tone spellings, selected octave/register, economical voicing choices and instrument-specific performance. Follow with one comparable exercise without the solution. The book is a manual: operational completeness matters more than theoretical explanation.

### P1 / controller semantics — Push key-change exercise omits Fixed mode

**Verified manuscript §§5/18; confirmed against Ableton's current Push manual.** Exercise 9 changes the selected reference key and asks for new sounding pitches, while specifying Chromatic and Fourths but **not** Push's **Fixed** switch. Ableton documents that Fixed **on** holds note positions while keys change, whereas Fixed **off** moves the pad grid so the root occupies the bottom-left pad. On identical gestures these settings lead to different resulting pitches. Note's Fourths layout and In Key-off semantics are described consistently with its official manual.

**Remedy:** Specify **Push Chromatic / 4ths / Fixed off** when same-pad-position transposition is intended; for a held-note-reference demonstration choose Fixed on explicitly. Add an exact three-note pad/pitch demonstration, noting the hardware/software display differences where needed. Avoid conflating pad colour emphasis with sounding note output.

### P1 / instructional load — the practice routine is infeasible as a single default for both reading routes

**Verified Part VI §20.** The advertised 20-minute routine uses five minutes for twelve roots of one scale and five minutes for all twelve roots and inversions of one chord quality, plus arpeggiation and a full progression through twelve roots. This is **25 seconds per key** for each five-minute block, before spelling and correction. The beginner eight-week plan assigns all major keys in week three and full repertoire transposition by week eight.

**Remedy:** Keep the twelve-key routine as an optional advanced standard. Define novice/intermediate/advanced variants with smaller root sets, repetition counts and explicit accuracy/tempo gates. Preserve *transposition-first*, rather than merely shortening the material or replacing it with the successor book's argument.

### P1 / production — inherited 53-page typesetting still contains disruptive breaks

**Confirmed on v1.3.1 direct PDF inspection; strongly inherited in v1.3.2 per release notes.**

- p. 2 ends with “On D, that becomes:” while the musical example \`D F A C\` starts p. 3.
- pp. 4–5 split the quick glossary and allow ugly intra-word breaking, e.g. *Enharmonic* and *Transposition*.
- p. 45 packs a five-column seventh-chord table into compact print. The reference rows may be mathematically correct but are not comfortable to consult from a music stand.
- pp. 52–53 split a section explicitly called “One-page philosophy”; p. 53 carries little content relative to usable page space.

**Remedy:** Keep the 160 × 230 mm book identity, but apply semantic keep-together rules to introductions/formulas, tune the glossary column ratios or use a two-column list, make the chord-reference page readable without reducing font, and rebalance the finale. Review printed at 100% size, not only in montage. Do not assume no out-of-page bounding boxes means good page design.

### P1 / navigation — contents page is not functional enough for a manual

**Inherited PDF finding.** Contents p. 6 lists sections and appendices but no **page numbers**; a PDF outline of 122 entries helps in capable viewers, but not when using a printout. In the examined v1.3.1 PDF the appendix source URLs were not reliably interactive (only two external link annotations overall). The same renderer/source persists in v1.3.2.

**Remedy:** Add page-numbered contents, clickable internal targets and a concise appendix-specific index; ensure visible reference URLs are hyperlinks; keep the document outline and add author metadata. Test digital and physical navigation independently.

### P1–P2 / accessibility — attractive page design is not a tagged accessible PDF

**Inherited artifact + same v1.3.2 renderer.** The archived v1.3.1 PDF reports **Tagged: no** and empty author metadata. The v1.3.2 generator inherits that architecture. Visually coloured pad/keyboard SVGs have descriptive Markdown alt strings, but PDF reading order, meaningful table structure, accessible figure alternatives and language must be checked as output, not inferred from Markdown.

**Remedy:** Determine whether the PDF can be made tagged with a suitable generator; provide a well-structured, accessible HTML edition (the build already generates an HTML intermediate) as a companion while PDF remediation is evaluated. Don't claim PDF accessibility compliance without testing it.

### P2 / theoretical terminology and note spelling convention

**Verified in source.** “Function” in the four-layer model sometimes serves as a stand-in for a **chord-tone degree formula** (e.g. \`1 b3 5 b7\`) rather than harmonic function in a progression (e.g. dominant). The distinction can be taught locally. Appendix B/C rightly includes double accidentals (Bbb, C##) but the early notation guide does not sufficiently explain how to read them at the keyboard. A few literal copy-edit problems remain (“in a In-Key layout” should be “in an In-Key layout”). English usage should be made consistent without stylistic homogenisation.

**Remedy:** Define degree formula vs. Roman-numeral/harmonic function in one concise passage, show one double-accidental equivalence in the appendix legend, correct typos and use a deliberate British-English copy-edit, retaining the source's compact instructive voice.

### P2 / modes and listening tests need more specific criteria

**Source §9, Exercise 5 and Appendix E.** Modal formulas and the four black-key examples are correct as written. However, “characteristic degree” is not necessarily unique to a mode (e.g. Ionian's major 7 also occurs in Lydian). Exercises say to improvise two bars without a stable tonic/accompaniment or criterion for recognising the defining alteration.

**Remedy:** Keep modes within the manual, but add a short controlled experiment: D Aeolian \`D E F G A Bb C\` versus D Dorian \`D E F G A B C\` over a retained D-minor tonic reference; then transpose both to another root, naming the altered sixth. Specify how to evaluate the hearing/transposition result, rather than adding an essay on embodied knowledge.

### P2 / source and build hygiene / contradictory planning references

**Verified.** \`.gitignore\` contains only \`.DS_Store\` and \`book.html\`, whereas edition builders generate version-specific Markdown/HTML files in tracked directories; normal builds can leave untracked outputs. \`README.md\` still says “transposition-first” should be reconsidered in v1.4, pointing at **closed issue #5**, although the two-book agreement explicitly **retains** the existing manual's premise and moves the other idea to independent successor-book issue #9. \`WORKLOG.md\` ends with “authorial review is pending” even though \`STATUS.md\` correctly records v1.3.2 as author approved.

**Remedy:** Tighten generated-file ignores; revise README to reflect separate-book decision and link to \`successor-book/CONCEPT.md\`; append release approval/verification to WORKLOG instead of rewriting history. Existing release source and filename should remain stable.

4. **Preserved earlier releases** as committed PDF objects. No historical asset is reported changed by PR #11.

## Recommended sequence, with acceptance checks

**Immediate: release safety.** Make v1.3 and v1.3.1 builder inputs immutable and prevent any archived output overwrite. Acceptance: an archive rebuild with an incorrect source hash fails rather than producing a falsely labelled edition.

**Next: correctness and device semantics.** Fix the one false chord-identity statement and Push Fixed instructions, add independently testable device examples and extend regression checks to the few selected formulas/progressions/voicings. Acceptance: note-and-octave expected results are checked and consistent with documentation, then real hardware where available.

**Then: pedagogical effectiveness.** Create a *single* full source-to-target, voiced transposition example; calibrate practice routes by level; obtain one pilot reader on each route. Acceptance: readers can complete the exercise without external explanation or interpretation of unspecified settings.

**Finally: production.** Page break and table fixes, contents/page numbers, hyperlink coverage, PDF author data, accessible HTML and print-scale preflight. Acceptance: no stranded musical formulas, a legible one-page seventh-chord table approach, a usable printed contents page, and an appropriately balanced final spread.

**Do not** replace the manual with the separate book, reset its intended audience, reintroduce the rejected v2 chapter, or update the published PDF from this review alone.
